Задание на практическую работу № 2
Тема работы: “Разработка кода через тестирование поведения”.
Данная работа является продолжением предыдущих практических работ. Основными
задачами текущей работы является приобретение навыков и знаний по разработке
через тестирование поведения (Behavior-Driven Development).
1. Изучите статью Дэна Норта [1] и опишите своими словами, почему автор
предлагает эволюционировать TDD в BDD, а также основной синтаксис языка,
получившего впоследствии название “Маринованный огурец” (Gherkin) [1,2,3].
2. Выберите и изучите один из фреймворков для реализации BDD-тестов в
соответствии с выбранным Вами ранее языком реализации приложения.
Например, Catch2 для C++, Cucumber для Java, Behave или pytest-bdd для Python и т.п.
3. Составьте описание не менее пяти различных Gherkin-историй (feature),
размещенных в отдельных .feature-файлах для модулей приложения, которое
было разработано в предыдущих заданиях.
Обязательные элементы:
-​ пользовательская история (после feature), описывающая название обобщенной
группы контрольных примеров, выгоду для конкретного пользователя (актора,
интересанта), что
он хочет сделать и выгоду от использования нового
функционала;
-​ в любой из трех Gherkin-историй нужно продемонстрировать корректное
обобщение типа Rule и Background;
-​ одна из Gherkin-историй должна содержать обобщение типа (бизнес-идея);
-​ сценарии, включая основные шаги Given, When, Then, ключевые слова And, But
и задание входной таблицы (последнее - хотя бы для одного теста);
-​ как минимум один из Gherkin-сценариев должен быть описан в императивном, а
один в декларативном стиле, см. пример на стр. 263 в [3];
-​ один из Gherkin-сценариев должен заключаться в сравнении двух основных
алгоритмах решения наукоемкой задачи и содержать элементы нагрузочного
тестирования (для разных данных), необходимо сравнить результаты с
соответствующим unit-тестом;
Основные шаги по планированию нагрузочного тестирования могут состоять в
следующем:
-​ определение ключевых характеристик для наборов данных, влияющих на их
эффективную обработку наукоемким алгоритмом, например, разреженность
матриц инцидентности; связность графа; отсутствие отрицательных весов и пр.;
-​ генерацию тестовых наборов данных разных размеров и характеристик,

4. Оформите отчет и загрузите его в форму в курсе. Временем сдачи задания
является время его защиты. Правила оценивания работы, оформления и сроки
размещены в курсе.
Структура отчета:
-​ титульный лист (см. шаблон);
-​ содержание работы;
-​ введение;
-​ описание плана BDD-тестирования, включающее:
-​ основы Gherkin;
-​ выбор фреймворка;
-​ описание тестовых случаев и BDD-тестов;
-​ описание экспериментов, включающее:
-​ условия проведения эксперимента (OS, RAM еtc),
-​ алгоритм(ы) генерации наборов данных,
-​ предварительный эксперимент по нахождению “максимальных” границ
производительности для алгоритмов;
-​ кодировку названий наборов данных и её расшифровку (в папке с
приложением должны быть датасеты с теми же названиями),
-​ сравнение работы двух фреймворков на одних и тех же (вычислительно
трудоемких) сценариях в случае группового проекта;
-​ профилирование;
-​ анализ результатов экспериментов, включающий:
-​ *проверку гипотезы и расчет доверительных интервалов;

-​ составление таблиц и графиков зависимостей времени выполнения и

-​ *) - с данной пометкой задание повышенной сложности;
-​ заключение, включающее описание:
-​ соответствие/несоответствие временной оценки алгоритмов в худшем
случае наблюдаемым экспериментам;
-​ выводы из анализа сходства двух распределений;
